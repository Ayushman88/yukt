# 0.14.1 CPU Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement approved 0.14.1 `start` / `wait` / `task[T]` on the existing host pool with 0.13.2 ownership, without adding mutex types, async, or GPU.

**Architecture:** `start` is a special call that moves arguments into a tracked task object, atomically enqueues it, and returns `task[T]`. `wait` atomically claims or blocks, then moves `T` out and `yukt_release`s the wrapper. Semantic analysis reuses `analyze_call` lookup and the Uninit/Owned/Moved machine. IR gains `Start` and `Wait`. The runtime adds a general task queue beside the existing range-parallel `yukt_parallel_for` path; one heap mutex covers tracker and size-class caches.

**Tech Stack:** Handwritten C++20 frontend (`yukt_compiler`), LLVM backend (`yukt_backend`), C11 runtime (`yukt_runtime`). C11 `<stdatomic.h>` for task state only. No new libraries. No language-level atomics.

### Critical runtime finding

`yukt_parallel_for` is a **batch range** API:

- macOS: `dispatch_apply`
- Linux: fill `yukt_par_jobs[32]`, broadcast, wait until the batch is empty

It is **not** a general queue. `start` must not call `yukt_parallel_for`. Reuse:

- macOS: `dispatch_async` on a global queue (same libdispatch host pool)
- Linux: the existing persistent `yukt_par_threads`, plus a new linked-list / deque of task pointers under `yukt_par_mu` (or a dedicated task mutex). Do not `pthread_create` per `start`.

`has_user_call` in `compiler/ir/lower.cpp` treats every `CallExpr` other than `count`/`zeros` as a user call that **disqualifies** parallelization. A `StartExpr` is a new node: `collect_loop_effects` will not see it unless updated. Planned-parallel detection must ignore `start`/`wait` when deciding whether the loop *would* have been parallel.

### Task 6: Runtime task object, claim, queue

**Files:**
- Modify: `runtime/yukt_runtime.h`, `runtime/yukt_runtime.c`
- Create: `tests/tasks/runtime_task_tests.c`
- Modify: `CMakeLists.txt` (add `yukt_task_runtime_tests` like `yukt_ownership_runtime_tests`)

**Interfaces:**

```c
typedef void (*yukt_task_fn)(void* args, void* result);

/* Allocate a tracked task, copy args pointer in, enqueue. Returns task*. */
void* yukt_task_start(yukt_task_fn fn, void* args, size_t result_bytes, size_t result_align);

/* Claim or block; copy result_bytes to out (nullable if 0); release wrapper. */
void yukt_task_wait(void* task, void* result_out);

void yukt_task_shutdown(void);
```

State word (`_Atomic int` or mutex-protected enum): `Queued=0, Running=1, Completed=2, Consumed=3`.

Claim: `compare_exchange Queued → Running`. Winner runs `fn(args, result_slot)`. Then store result, `Running → Completed`, signal waiters.

`yukt_task_wait`:

1. If CAS `Queued → Running` succeeds: run `fn` inline; go to Completed; consume.
2. Else if Running: wait on `pthread_cond` / semaphore until Completed; consume.
3. Else if Completed: consume.
4. Consumed or NULL: `die("double wait or untracked task")`.

Consume: CAS `Completed → Consumed`, memcpy result, `yukt_release(task)`.

Queue:

- macOS: `dispatch_async(dispatch_get_global_queue(QOS_CLASS_DEFAULT, 0), ^{ yukt_task_worker_try(task); })` where `yukt_task_worker_try` CAS-claims and runs or returns.
- Linux: enqueue on a task list; `pthread_cond_signal` a worker. Extend `yukt_par_pool_worker` **or** add `yukt_task_pool_worker` on the same `yukt_par_threads` after `yukt_par_ensure_pool(ncpu)`. Do not create a thread per task. A worker that is inside `yukt_parallel_for` must not interleave a `start` body onto that range job in 0.14.1 — use the same threads only when they are idle on the task queue, **or** keep a dedicated persistent task worker count = `ncpu` created once. Locked simpler path: dedicated persistent task workers (`yukt_task_ensure_pool`), separate from the range-batch array, still capped at `YUKT_PAR_MAX_TASKS` (32). Range parallel and tasks may run concurrently. Heap mutex serializes alloc.

Do not execute a task twice. Runtime test: two threads call `yukt_task_wait` / worker claim on one task; `fn` increments an atomic counter; assert counter == 1.

## Unresolved / locked decisions (do not reopen in implementation)

1. **Reserved vs contextual keywords:** reserved. Rename stdlib/`start` identifiers. Not redesigned.
2. **Wait does not steal other jobs:** only the waited-for task may run inline, and only on a won `Queued → Running` claim.
3. **Running-wait cycles can hang.** No timeout.
4. **Dedicated Linux task workers** (persistent, ≤32), not `yukt_parallel_for` batch slots.
5. **`wait` of `ref task[T]` is rejected.** Owner must be moved in.
6. **Unused task is a compile error.** No implicit drop of a live job.
7. **Linux CI on `d296d80` failed** for GCC missing-field-initializers. Fix construction style; do not claim Linux until Ubuntu is green.
8. Version remains 0.13.6 until a 0.14.1 release is authorized.
